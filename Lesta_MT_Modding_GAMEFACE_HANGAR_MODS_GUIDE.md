## 1. Что нужно знать о Gameface

- **Coherent Gameface** — движок интерфейса клиента (HTML/CSS/JS вместо старого Flash/Scaleform). Старые ангарные моды на `.swf` несовместимы в принципе — это перенос как новая разработка: вёрстка → HTML/CSS, логика → JS, серверная часть → Python-модуль.
- Интерфейс ангара — набор **view** в движке. Мод может работать двумя способами (см. §2).
- Референс-файлы мод-пака (держать под рукой):
  - `\wot.gameface-v1.1.6\resources\in\gui\gameface\js\index.js` — инициализация Gameface, Resource Injector / ModInjectModel;
  - `mods\libs\` — библиотеки мод-пака.

## 2. Две архитектуры ангарного мода

### 2.1 Собственное wulf-окно (так работают SilverHUD и MarksHUD)
Мод создаёт собственное окно движка со своим HTML-контентом. Пример регистрации из SilverHUD: класс окна `SilverHudView`, resID-ключ `user.silverhud.panel`, layoutID `114207`. Второй подтверждённый экземпляр: `MarksHudView`, ключ `user.markshud.panel` — **несколько окон модов на слое WINDOW(7) спокойно живут вместе**.

**Плюсы:** полная независимость от DOM ангара; свободное позиционирование и перетаскивание; чистое удаление при выходе из ангара.
**Минусы:** видимостью надо управлять самому (окна игры перекрывают панель) — решается watchdog'ом (§5).

**Когда выбирать:** панель/виджет/счётчик поверх ангара.

### 2.2 Resource Injector (рендер внутри view ангара)
Мод инжектит свои DOM/CSS/JS прямо в существующие view клиента (механика ModInjectModel, см. `index.js` мод-пака).

**Плюсы:** видимость решается сама (контент исчезает вместе с экраном); нет борьбы за слои.
**Минусы:** зависимость от структуры DOM клиента — патчи могут ломать селекторы; нет свободного перетаскивания.

**Когда выбирать:** дорисовка ВНУТРИ родных экранов (кнопки в карточке танка, доп. поля в существующих окнах).

### Как выбрать

## 5. Видимость и клики: структурный watchdog

**Проблема:** игра открывает десятки окон (ESC-меню, ЛБЗ, задачи, достижения, окна чужих модов...). Перечислять вручную нельзя — список всегда неполный (урок v3.5.0: пропустили BattlePassEntryPointView — панель пропадала).

**Решение (v3.7.0+, подтверждено):** скрывать панель, когда на экране есть **любое** окно блокирующего слоя, и показывать, когда блокеров нет.
BLOCK_LAYERS = [5, 6, 7, 8, 10, 11]
IGNORE_TYPES = [8, 33, 49, 65, 81, 98, 114]

хук wulf Window — создание/закрытие ЛЮБОГО окна = триггер переоценки
on(window opened / closed):
blockers = [w for w in live_windows
if w.layer in BLOCK_LAYERS and w.type not in IGNORE_TYPES]
if blockers and panel_visible: HIDE()
if not blockers and not panel_visible: SHOW()

on(hangar populate): создать окно панели, если его нет
on(hangar dispose): скрыть/разобрать

text

### 5.1. HIDE = `hide(destroy=True)`, а НЕ CSS

**Главный урок v4.0.0** (проверено на SilverHUD): CSS `visible=0` (флаг модели + `display:none` в JS) убирает панель из **рендера**, но **не снимает hit-test прямоугольник wulf-окна**. Прямоугольник продолжает существовать на движковом уровне, и клики по нативным окнам игры (Оборудование, Боекомплект, Снаряжение, диалоги), попадающие под геометрию панели, **не доходят** до них.

Ни `hide()` (без параметров), ни CSS-переключение проблему не решают — окно остаётся в input-стеке.

**Единственный штатный способ:** `WINDOW.hide(destroy=True)`. Нативное окно уничтожается вместе с hit-test прямоугольником. Подпись метода — `frameworks.wulf.windows_system.window.Window.hide(self, destroy=False)`.

Цена: JS-состояние страницы теряется, показ = пересоздание окна (~0.3–1.0 с, пока грузится Gameface-страница). Приемлемо; визуально панель просто возвращается на место.

### 5.2. SHOW = пересоздание через watchdog

При показе `WINDOW is None`, и `set_visible(True)` вызывает `_recreate_soon(...)` → `WINDOW_LOST_HANDLER` (`_recreate_window` в `app.py`) → `view_mod.create_window(...)`. Позиция берётся из конфига, окно встаёт на место, JS загружается заново.

### 5.3. Восстановление окна после возврата из боя

`is_window_alive()==True` — недостаточное условие, что панель покажется. Окно может быть живым и при этом невидимым. Две причины:

**Причина A: залипшие блокеры.** См. §5, «Правила» — клиент рвёт battle-space целиком, `_removeView` для боевых вьюх не вызывается. Лечение: в `_on_hangar_entered` чистить `_sf_blockers` и `_wulf_blockers`, сбрасывать `_last_vis_key`.

**Причина B: мёртвая GF-страница при живом окне.** Boot-страж (`BigWorld.callback(BOOT_TIMEOUT, _check_page_boot, uid)`) убивается сменой space. Лечение: в `_on_hangar_entered` проверять `READY_SEEN`, и если окно живое, но `js ready` не приходил — `destroy_window()` + `_try_create_window(0)`.

Шаблон `_on_hangar_entered` с обеими проверками:

```python
def _on_hangar_entered():
    global _hangar_ready, _recreate_budget, _ever_entered
    global _own_uid, _last_vis_key
    _hangar_ready = True
    _ever_entered = True
    _recreate_budget = 12
    if _sf_blockers:
        _log(u'hangar entered: clearing stale SF blockers %r'
             % sorted(_sf_blockers))
        _sf_blockers.clear()
    if _wulf_blockers:
        _log(u'hangar entered: clearing stale WULF blockers %r'
             % sorted(_wulf_blockers))
        _wulf_blockers.clear()
    _last_vis_key = None
    try:
        if not view_mod.is_window_alive():
            _try_create_window(0)
        elif not view_mod.is_page_ready():
            _log(u'hangar entered: window alive but page NOT ready — recreating')
            view_mod.destroy_window()
            _try_create_window(0)
        else:
            _own_uid = getattr(view_mod.WINDOW, 'uniqueID', None)
            view_mod.push_panel_position()
        _push_stats_to_ui(force=True)
        _recompute_panel_visibility(force=True)
        _log(u'hangar entered: own uid=%s' % _own_uid)
    except Exception:
        _log(u'on_hangar_entered CRASHED:\n%s' % traceback.format_exc())
```
В view.py нужны два хелпера:
```python
READY_SEEN = False

def is_page_ready():
    return bool(READY_SEEN)
```

и установка READY_SEEN = False в create_window сразу после WINDOW.load(), READY_SEEN = True — в _onReady модели.


		

### Правила

- Хуки: `wulf Window` (триггер watchdog), `hangar populate/dispose`, `LoaderManager.loadView` и `ViewContainer.addView` (SF-вьюхи).
- **HIDE = `hide(destroy=True)`.** Ни CSS-only, ни `hide()` без параметров, ни off-screen `move()` (тот вообще клэмпится движком в `(0,0)` — урок 3.8.0).
- SHOW = пересоздание окна. Позиция из конфига, `_retry_position` до успеха.
- **Не хардкодить uid view** — он меняется между сессиями. Своё окно опознавать по классу (`SilverHudView`, `TankCardView`).
- **Слой WINDOW(7): блокируют только МОДАЛЬНЫЕ окна** (`isModal()` → флаги `WINDOW_MODALITY_MASK=12288`). Не-модальные панели чужих модов — тоже WINDOW/flags=1 — блокировщиками НЕ считать, иначе две панели взаимно прячут друг друга (урок MarksHUD 1.0.1: SilverHUD + MarksHUD в одном ангаре).
- **Дедупликация `_recompute_panel_visibility`** (v4.0.0): сравнивать `(visible, sorted(sf_blockers), sorted(wulf_blockers))` с предыдущим значением, выходить при равенстве. Иначе на каждый чих клиента (hover, tooltip, focus) летит `[VIS]` в лог, десятки раз в секунду. Это не оптимизация логов, а предотвращение лагов: лишние вызовы `set_visible` дёргают модель wulf.
- **`onWindowStatusChanged` из `IGuiLoader.windowsManager`** получает событие на **любое** изменение статуса **любого** окна клиента. При подписке нужно кэшировать константы `WindowStatus.LOADED` и `WindowStatus.DESTROYED` — определить функцию `_status_consts()` с импортом из `frameworks.wulf.gui_constants` и фолбэком `(3, 5)` (числовые значения в клиенте 1.45: `LOADED=3, DESTROYED=5`).
- **Очистка блокеров при входе в ангар — обязательна.** При выходе из боя клиент рвёт весь battle-space целиком: `ViewContainer._removeView` для боевых SF-вьюх и `_on_wulf_showing(HIDDEN)` для боевых wulf-окон **не вызываются**. `_sf_blockers` и `_wulf_blockers` остаются наполненными (`classicBattlePage`, `AchievementsComponentInjector`, `EnemyAnnounceInjector`, `HitIndicatorInjector`, `NextTankHudView`...), `visible` считается `False`, панель не показывается — навсегда. В `_on_hangar_entered` первым делом чистить оба множества и сбрасывать `_last_vis_key`. Если что-то в ангаре реально открыто — оно пере-добавится через `_on_sf_added`/`_on_view_load`.
- **Проверка страницы при входе в ангар (`is_page_ready`).** `is_window_alive()==True` **не означает**, что GF-страница загружена. Boot-страж `BigWorld.callback(BOOT_TIMEOUT, _check_page_boot, uid)` **не переживает смену space**: если окно создано в бою за секунды до перехода в ангар, `_check_page_boot` не сработает, `js ready` не придёт, а окно останется живым. В `_on_hangar_entered` проверять: окно живое, но `READY_SEEN == False` → `destroy_window()` + `_try_create_window(0)` в стабильном space'е ангара.

## 6. Позиция окна: три правила

1. **Создавать окно скрытым, позиционировать ДО первого показа.** Окно без позиции = вспышка в левом верхнем углу.
2. **HIDE = `hide(destroy=True)`, окно НЕ двигается.** Off-screen `move(-10000,-10000)` клэмпится движком в `(0,0)` — это давало «мерцание в левом верхнем углу» при открытии окон и «В БОЙ» (урок 3.8.0). CSS-скрытие (visible=0) убирает панель из рендера, но **не снимает hit-test прямоугольник wulf-окна** — клики в нативные окна игры под геометрией панели не проходят (урок 4.0.0). Уничтожение окна через `hide(destroy=True)` решает и то, и другое: окна нет — нет и перехватчика.
3. **Санити-чек сохраняемой позиции:** игнорировать `(0,0)`, отрицательные и запредельные координаты. Без этого позиция дрейфует (кейс: 536,129 → 540,128).

Перетаскивание — за всю карточку, позиция сохраняется сразу при отпускании.

| досье танка: `itemsCache.getVehicleDossier(intCD).getRecordValue('achievements', ...)` | `damageRating` (рейтинг урона, %×100), `movingAvgDamage` (средний урон) — источник «отметок на стволе» в MarksHUD |

- Сессионная статистика (заработок/расход за бой) считается на Python: дельты до/после боя.
- Обмен Python ↔ JS — механизм мод-пака; готовые рабочие вызовы смотреть в коде SilverHUD (Python-модуль + JS-обвязка карточки).

- **Совместимость со старым Flash-модом:** конфиги и накопленная статистика — в тех же файлах и форматах (`config.json`, `stats.json` в `mods/configs/<mod>/`) — данные старого мода подхватываются без переноса.

## 9. Грабли (проверено на себе)

1. **Мерцание в (0,0)** при открытии окон / «В БОЙ» → off-screen `move(-10000,-10000)` при HIDE: движок клэмпит его в `(0,0)`, и в течение лага (пока не применится CSS) панель видна в углу. Лечение: **никогда не двигать окно при скрытии**, только `hide(destroy=True)` (v4.0.0).
2. **Дрейф сохранённой позиции** → в сохранение попадают «грязные» прочитанные координаты. Лечение: санити-чек (§6.3).
3. **WaitingView не ловится** слоями 5–11 (он на слое 16, flags=98) → важен правильный ignore-список; CSS-скрытие страхует от вспышек.
4. **CSS-only скрытие не снимает hit-test** (главный урок v4.0.0). Панель исчезает визуально, но клики по нативным окнам игры (Оборудование, Боекомплект, Снаряжение, диалоги) под её геометрией **не проходят**. Единственный штатный способ убрать hit-test — `WINDOW.hide(destroy=True)`. Восстановление — пересоздание окна (позиция из конфига, ~0.3–1.0 с на boot Gameface-страницы). Это **не** «регрессия v3.5.0»: там destroy/recreate дёргали окно на каждый возврат в ангар из-за ошибок в watchdog — здесь destroy только по факту открытия/закрытия блокирующего окна, а позиция берётся из конфига.
5. **Ручные списки окон** → всегда неполны. Только структурный watchdog.
6. **uid между сессиями меняется** → опознание своего окна только по классу.
7. **Разрешение:** карточка фиксированного размера (в SilverHUD 260×310), тестировалось на 2560×1440 — на других разрешениях проверять позиционирование отдельно.
8. **Number-свойства wulf — только int** (`_addNumberProperty`, `_setNumber`; биндинг `addNumberField`). float = `TypeError` при бинде модели → окно ВООБЩЕ не создаётся, watchdog сжигает бюджет пересозданий вхолостую (кейс MarksHUD 1.0.1 → исправлено в 1.0.2: дробь передаётся int-ом в сотых долях %, JS делит на 100).
9. **Модальность WINDOW(7):** считать блокером каждое окно слоя 7 = «панели других модов прячут друг друга». Блокеры на 7 — только модальные (маска 12288).
10. **Блокеры залипают после боя** (наблюдалось на TankCardHUD 1.4.6 и MarkBattle 1.0.6). Клиент при выходе из боя рвёт весь battle-space целиком: _removeView для classicBattlePage, AchievementsComponentInjector, EnemyAnnounceInjector, HitIndicatorInjector не вызывается; _on_wulf_showing(HIDDEN) для NextTankHudView — тоже. В логе видно [CT] + X -> BLOCK без парного [CT] - X -> UNBLOCK. Симптом: hangar entered: own uid=..., потом тишина, панели нет, [VIS] sf=N wulf=... -> visible=False на каждом шаге. Лечение: в _on_hangar_entered чистить _sf_blockers и _wulf_blockers (§5.3, шаблон).
11. **Boot-страж не переживает смену space.** BigWorld.callback(BOOT_TIMEOUT, _check_page_boot, uid) созданный в бою перед переходом в ангар — не срабатывает (callback убит сменой space). Окно живое, is_window_alive()==True, READY_SEEN==False, js ready в логе отсутствует. Панель невидима. Симптом в логе: window created: uid=31, deferred pending position: x=500 y=86, hangar entered: own uid=31 — и ни одной строки js ready / page boot TIMEOUT между ними. Лечение: проверка is_page_ready() в _on_hangar_entered (§5.3, шаблон) — при живом окне и READY_SEEN==False делать destroy_window() + _try_create_window(0).

## 10. Чек-лист портирования старого мода

1. **Инвентаризация:** что мод показывает, откуда данные, какие экраны затрагивает. Если это `.swf` — вёрстка → HTML/CSS, логика ActionScript → JS, питоновская часть переписывается под текущее API.
2. **Архитектура** по §2: панель → своё окно; дорисовка в родных экранах → инжекция.
3. **Скелет:** копия SilverHUD; переименовать тег логов, класс окна/view; размеры карточки под задачу.
4. **Вёрстка:** фиксированный размер, тёмная карточка, крупные шрифты (образец — «ЧИСТОЕ СЕРЕБРО» в SilverHUD).
5. **Данные:** только нужные подписки из §7. `g_currentVehicle` — подписка в ангаре. Модель wulf: все number-свойства int, дробные — в сотых долях (§9.8). Старые конфиги/статистика — в тех же форматах для совместимости.
6. **Watchdog:** оставить как в SilverHUD — универсален (§5). BLOCK/IGNORE менять только при доказанной необходимости.
7. **Позиция:** правила §6 (создать скрытым, позиция до показа, санити-чек).
8. **Сборка/установка:** §3, версия инкрементируется.
9. **Приёмка:** тест-сценарий §11 — полностью.

## 11. Тест-сценарий приёмки (прогонять после каждого релиза)

1. Вход в ангар → панель на сохранённой позиции, появляется мгновенно.
2. По очереди: ИССЛЕДОВАТЬ, ЛБЗ, ЗАДАЧИ, ДОСТИЖЕНИЯ, Экипаж, кастомизация → панель скрылась **без мелькания в углу**.
2a. Открыть **ОБОРУДОВАНИЕ**, **БОЕКОМПЛЕКТ**, **СНАРЯЖЕНИЕ** → панель скрылась, **все кнопки под геометрией панели кликаются** (не должны быть «глухими»). Это проверка hit-test: если панель пропала визуально, но клик в кнопку нативного окна под её прямоугольником не проходит — значит, скрытие сделано только через CSS, а не `hide(destroy=True)`.
3. Закрыть каждую → панель вернулась мгновенно, позиция не съехала.
4. Модальное окно (продажа и т.п.) → скрылась/вернулась.
5. «В БОЙ» (окно ожидания) → без вспышки в (0,0).
6. ESC / меню настроек → скрылась.
7. Полный перезапуск клиента → позиция та же, данные корректны.
8. Логи чистые: без ошибок, каждый HIDE/SHOW с понятной причиной. **Не должно быть повторов `[VIS] ...` с одинаковым содержимым** — это признак отсутствующей дедупликации `_recompute_panel_visibility` (§5).
9. **Соседство модов:** вместе с другой GF-панелью (SilverHUD/MarksHUD) — обе видимы, окно модального ESC/диалога прячет обе.
